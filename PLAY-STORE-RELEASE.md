# Mobcode — Play Store release checklist

Case by case, step by step, from build artifact to the Play Console record. No
step claims Play approval — until you have actually been approved, the app is
**not** approved.

---

## 0. What you upload

| Artifact | Use | Where |
|---|---|---|
| `Mobcode-release.aab` | Production upload to Play | `dist/android/playstore/Mobcode-release.aab` |
| `Mobcode-release.apk` | Direct installs / sharing | `dist/android/release/Mobcode-release.apk` |
| `Mobcode-debug.apk` | Local testing only — never upload | `dist/android/debug/Mobcode-debug.apk` |

## 1. Pre-upload checks

- [ ] `apksigner verify --print-certs Mobcode-release.aab` reports exactly one
      valid signer (`CN=Mobcode`) and no `-Werror` signature problems.
- [ ] `aapt2 dump badging` shows: `package: name='com.mobcode.app'`,
      `versionName='1.0.0'`, `versionCode='1'`,
      `targetSdkVersion: '36'`, `minSdkVersion: '24'`.
- [ ] Target API 36 confirmed (Play requirement for new apps as of the current cycle).
- [ ] Permissions in the manifest are only `INTERNET` + `ACCESS_NETWORK_STATE`
      (no dangerous permission banners required).
- [ ] You are enrolled in **Play App Signing** (Play keeps the signing key, so
      you upload with the *upload key* — that's what `mobcode-upload.keystore` is for).
- [ ] `com.mobcode.app` availability is checked by the Play Console during
      upload — it must show as free/self-owned before you proceed.

## 2. Play Console steps

1. Create an app record: *Create app → All apps → New app*.
   * Name: **Mobcode**
   * Default language: English
   * Type: App
2. **App content →** work through the questionnaires:
   * Data safety → fill per `DATA-SAFETY-CHECKLIST.md`.
   * Ads: "No ads".
   * Content rating questionnaire → matches the "Everyone" profile (no violence, no mining, no chat-of-strangers features; AI assistant content generated on your own backend only). Save the rating certificate.
   * Privacy policy URL → host `PRIVACY-POLICY.md` at a public URL (e.g. your Render backend static path or a gist/page) — **required**.
   * App access: **All functionality is accessible without special access**, with
     reviewer note "Your backend URL + test OpenCode conversation account" below.
   * Restricted content: declare none.
3. **Main store listing** per `PLAY-STORE-LISTING.md`.

### Reviewer access instructions (paste into App access)

The app connects to your own private backend. Provide reviewers with a demo URL
and assist them through the connect screen:
- Server URL: `https://<your-render-url>` (enter on the welcome screen).
- Optional password: only if you configured one for the backend.
- After connecting, everything in the app is self-explanatory (Chats, New,
  Providers, Settings tabs).

4. **Internal testing** first: upload the AAB to the Internal track, add yourself
   and one device, then install the internal-test APK through the Play track.
5. After *internal* testing is green, move to Production (full track) when you
   are ready — **do not submit without your explicit permission** (mine to you).

## 3. Store assets to prepare

| Asset | Requirement | Source |
|---|---|---|
| App icon (512×512 PNG32) | Safe-area-compliant rounded | `dist/meta/icon-512.png` (generated from assets/icon.png) |
| Feature graphic | 1024×500 JPG/PNG | `dist/meta/feature-graphic.png` (generated by `scripts/play-artwork.sh`) |
| Phone screenshots | ≥ 2, 16:9 or 9:16, min 320px, max 3840px | device screenshots (emulator not available here — use your phone) |
| 7" / 10" screenshots | optional for tablets | optional |

`scripts/play-artwork.sh` in this repo generates the 512 icon and a branded
feature graphic; screenshots must be captured from a device/emulator — see
ANDROID-TEST-REPORT for what could not be produced in this environment.

## 4. Post-approval maintenance

* Every future release must keep `versionCode` strictly increasing and expose
  the same signing identity (same upload key + Play-managed signing key).
* Rolling production releases gradually ("Staged rollout") is recommended for
  an app that talks to a private backend.
* Keep the privacy policy URL alive for the lifetime of the listing.
